# מחשבון סכם והמלצת מיון · רפואה שש־שנתי אריאל

גרסה 3.0. כלי לא רשמי; סקר התנדבותי אינו מדגם מייצג ואינו תחזית קבלה.

## התנהגות המשתמש

- נדרשת התחברות Google ואימות בשרת לפני פתיחת שדות הציונים והחישוב.
- לחיצה על „חשב ושמור את הציונים” שומרת אוטומטית את הציונים התקינים ומחשבת על הנתונים שהשרת מחזיר. התחברות לבדה והקלדות ביניים אינן שומרות ציונים.
- בשמירה חוזרת אותו חשבון מעדכן את הרשומה שלו. בקשה חוזרת עם אותם נתונים אינה מוסיפה רשומה.
- מוצגים מצבי שמירה, כשל וניסיון חוזר. כשל רשת אינו מוצג כהצלחת שמירה; לאחר timeout ייתכן שהשרת הספיק לשמור, וניסיון חוזר בטוח מבחינת כפילויות.
- יציאה או פקיעת ההתחברות נועלות את הטופס ומנקות את נתוני החשבון מהמסך.

## שני מקורות, מדגם מזוהה אחד

`תגובות לטופס 1` נשארת מקור התשובות של Google Forms. `מחשבון` מכילה רשומה לכל מזהה חשבון Google, ושדות עזר פנימיים להתאמת המקורות. השרת מחזיר מאגר לוגי מאוחד; הוא אינו מייצר תשובות מלאכותיות ב־Google Forms ואינו משנה את מסך Responses של הטופס.

- זהות המחשבון מבוססת על `sub` מאומת של Google, לא על מייל שהלקוח שולח.
- מייל מאומת משמש להתאמה בין המקורות, ולא כמפתח החשבון הראשי.
- התאמה אוטומטית מבוססת מייל נתמכת ב־Gmail ובחשבונות Workspace עם claim מסוג `hd`. חשבונות Google עם מייל חיצוני יכולים לשמור לפי `sub`, אך התאמתם לתשובת טופס מחייבת אימות נוסף; טופס חיצוני לא משויך אינו נספר בינתיים.
- כתובת שכבר קושרה לחשבון אחר לא תועבר אוטומטית בין חשבונות.
- ציונים זהים אינם הוכחת זהות. אנשים שונים עם אותם ציונים נשארים רשומות נפרדות.
- אם קיימות כמה תשובות טופס מזוהות באותו מייל, נבחרת האחרונה לפי חותמת הזמן.
- שמירה במחשבון מתעדת את גרסת נתוני הטופס שנצפתה. שינוי מאוחר בנתוני הטופס מחליף את הגרסה הישנה באיחוד; שמירה מפורשת נוספת מהמחשבון מעדכנת שוב את הנתונים. בהיעדר היסטוריית עריכות, שינוי שהוחזר בדיוק למצבו הקודם אינו ניתן לזיהוי.
- תשובות ללא מייל אינן ניתנות לשיוך אוטומטי בדיעבד. הן נשמרות במקור אך אינן נכנסות למדגם המזוהה. מספרן מוצג בנפרד.
- גם רשומת מחשבון מהגרסה הישנה שטרם קושרה למנגנון החדש תמתין להתחברות בעליה במקום להיספר לצד תשובת טופס שאולי שייכת לאותו חשבון.
- ללא מספיק נתונים בני־השוואה בשתי המכסות תוצג הודעת חוסר נתונים במקום המלצה מטעה.

## התקנה ושדרוג

1. OAuth client מסוג Web application עם origin מדויק: `https://naaman6.github.io`. אין צורך ב־Client secret באתר.
2. הטופס חייב להישאר במצב איסוף מייל `VERIFIED`, עם הודעת פרטיות מתאימה. אין להחליף אותו בהקלדה עצמית של מייל.
3. בעת החלפת הקוד ב־Apps Script יש לשמר את `CONFIG.SALT` הפרטי הקיים בתוך סביבת Apps Script בלבד. אין להחליפו או להוציאו לצ'אט, לריפו, לצילומי מסך או לקובץ מקומי. הקובץ הציבורי מכיל placeholder בלבד.
4. אין להריץ `configureForm` מהגרסה הקודמת: היא ביטלה איסוף מייל. הגרסה הזאת אינה כוללת את הפונקציה ואינה משנה הגדרות טופס.
5. לבדוק את הקוד, לשמור אותו, ולעדכן את הפריסה הקיימת לגרסה חדשה. לשמור על כתובת `/exec`, `Execute as: Me`, `Who has access: Anyone`. הרשאות הגישה לנתונים נאכפות בשרת בכל בקשה.
6. לפרסם את `index.html` המתאים לגרסת השרת. גרסת הממשק וגרסת API חייבות להיות 3; קיימת חסימה מפורשת כשאין התאמה. יש לתאם את שני העדכונים כדי לצמצם חלון אי־זמינות.
7. כל שמירה, פריסה ועדכון GitHub כפופים לאישור נפרד של בעל הפרויקט.

השרת יוצר או מרחיב את לשונית `מחשבון` בשמירה הראשונה, תחת נעילה. השדרוג אינו מוחק שורות מהטופס. אין צורך בטריגר או בהרצת פונקציית הכנה.

מצב OAuth Testing לבדו אינו מוכיח שההתחברות מוגבלת למשתמשי בדיקה: Google מחריגה התחברות בסיסית באמצעות Sign in with Google, בתנאים המפורטים ב־[Manage App Audience](https://support.google.com/cloud/answer/15549945?hl=en).

## אבטחה ופרטיות

- אימות Google בצד השרת, כולל בדיקת `aud`, `iss`, `exp`, `sub` ומייל מאומת. ראו [Google ID token verification](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).
- אין חשיפה של סודות, אסימונים או מיילים ביומנים. הודעות שגיאה אינן מחזירות תוכן גולמי מגוגל.
- המיילים של Google Forms זמינים למנהלי הטופס והגיליון, כפי שנמסר למשיבים. במחשבון נשמרים מזהים מגובבים עם מלח סודי, לא מייל או שם גולמיים.
- המזהים הפנימיים הם פסאודונימיים, לא הבטחת אנונימיות. ה־API מחזיר למשתמש מחובר רק ציונים, מסלול וסימון הרשומה שלו; לא מזהים של אחרים.
- `GET` ציבורי מחזיר רק מצב וגרסת API. נתוני הסקר מתקבלים ב־POST מאומת.
- הסרת העותק הסטטי מהגרסה החדשה אינה מוחקת גרסאות קוד ישנות שכבר פורסמו.
- אין אחסון של אסימון התחברות בדפדפן מעבר לזיכרון העמוד.

## בדיקות לפני הפעלה

בדיקות מקומיות עם נתונים בדויים מכסות חסימת משתמש לא מחובר, אימות לפני פתיחת השדות, שמירה אוטומטית בחישוב, ניסיונות חוזרים, שינוי ציונים, מניעת התחזות, איחוד טופס ומחשבון, הפרדת ההיסטוריה, שגיאות ויציאה.

בדיקות מדומות אינן תחליף לבדיקה מבוקרת לאחר הפריסה מול Google והגיליון האמיתיים. אין להזין רשומות ניסוי לסקר בלי אישור מתאים.
